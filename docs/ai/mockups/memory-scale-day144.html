측정 기준과 눈금 읽기
방식좋은 점검토할 점
고정 60 / 100 / 200 / 500 / 1,000같은 각도가 언제나 같은 장수초과하면 끝 눈금에 정지하고 실제 장수를 별도 표시. 작은 수량은 넓은 범위에서 구별하기 어려워.
단계 확장 (추천 후보)60→100→200→500→1,000→이후 2·5·10배로 확장61장에서 범위가 100으로 바뀌며 바늘이 뒤로 이동해. 최대 눈금을 항상 보여 줘야 해. 실행 도중 범위는 고정해.
기간별 측정월별 집계 함수를 재사용할 수 있어현재 앱에는 기간 선택기가 없어. 전체·연간·월간 도입과 기존 연간 비교를 없앨지는 별도 승인 대상이야.

추천 측정 대상: futureMailState=NONE인 일반 보관 엽서. 미래로 보낸 엽서 포함 여부는 사용자가 확정해야 해. 무게·책갈피·중요도 점수는 계산하지 않아.

구조·접근성·실제 앱 적용 메모

본체와 눈금판은 고정, 지지 피스톤은 길이 변화, 받침대·정착 엽서는 같은 좌표계, 바늘은 (220,269)의 고정 축이야. 하중별 spring step을 중첩하고 마지막 프레임은 정확한 목표값에 정착해. 엽서는 최대 12겹이며 더미 두께는 실제 장수에 비례하는 그래프가 아니야. 기본 도형→색상→질감은 동일한 기하 구조를 사용해.

이 HTML의 종이 결은 절차적 선과 점으로 만든 비교 질감이야. 앱의 실제 종이 타일과 동일하다고 보장하지 않아. 실제 Compose에서는 Canvas/Path/graphicsLayer로 구조를 만들고 기존 종이 타일 재사용을 검토할 수 있어. 봉투·도착 상태·D-day는 기존 미래 우체통 컴포넌트를 유지하는 제안이야. 이곳의 ↗는 화면을 이동하지 않아.

운영체제의 움직임 줄이기도 반영해. 결과는 종료 때 한 번 안내하고, 장식용 눈금은 개별 발화하지 않아. 작은 화면에서는 세부 눈금보다 정확한 장수 텍스트가 판독 기준이야. 최종 Android 접근성·작은 화면·큰 글자는 별도 검증이 필요해.
