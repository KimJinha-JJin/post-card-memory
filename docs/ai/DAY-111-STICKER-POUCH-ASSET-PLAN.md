현재 외곽 기준(세부 가위질 jitter는 약 0.5~0.55 논리 단위, 픽셀까지 생성 모델이 맞춘다고 보장하지 않아):

- **앞판 B:** (3,30) → (46,29) → (56,35) → (66,38) → (76,35) → (86,29) → (129,31) → (127,86) → (5,87). PNG 좌표는 각각 ×4.5. 얕은 중앙 홈은 유지하고 앞판 아래쪽은 닫힌 불투명 종이야.
- 앞·뒤는 같은 주머니의 대응 부품이지만 기존 코드부터 뒷판이 약간 안으로 들어간 외곽이야. 두 실루엣을 억지로 완전히 동일하게 만들지 말고 현재 작은 offset과 바닥 관계를 보존해.
- 스티커 Box의 정적 y 범위는 3~33, 7~37, 2~32dp야. 앞판 윗변은 위치별 y=29~38dp라 현재 가림은 조각마다 달라. 회전·누끼 내부 여백도 있어 가리는 비율을 한 숫자로 단정하지 않아. 원본 좌표를 보존한 첫 자산을 합성해 확인한 뒤 사용자 QA로 조절해.
- `스티커 통`은 기존 (12,39)dp/11sp, 개수는 (12,71)dp/8sp에 앱이 그려. PNG의 그 자리는 대비가 낮고 조용해야 해. 고정 글자·개수·사진 조각을 PNG에 넣지 않아.

**메모리 추정:** ARGB_8888 전체 원본 decode 기준 `594×396×4=940,896B`, 약 0.897MiB/장, 두 장 1.79MiB. 현재 3x에서 화면 크기로 구운 두 장은 약 0.798MiB라 원본 전체 decode를 쓰면 닫힌 파우치에서 약 1.0MiB 증가할 수 있어. 보관함의 작은 코드 그림·장면 전환 중 동시 상주·Resources/Coil 캐시·GPU 텍스처·업로드 비용은 별도야. 실측하지 않았어. 압축 PNG 바이트와 APK 증가는 아직 산정할 수 없고 실제 자산·패키징 뒤 확인해야 해. 이미지가 제공되면 header/alpha/bbox/용량부터 검사하고 decode 정책을 최소 범위에서 정해.

## 제작 프롬프트 A — 파우치 뒷판

STANDARD 2.2의 **종이 배경·재질 자체 적용 제외**로 분류했어. 실사 물체 사진 블록을 강제하면 입체 가방을 만들 수 있어서 넣지 않았어. 종이 자체에 관한 E절과 사용자가 지정한 미세 인쇄 질감을 적용해. 생성 자산 한 장은 한 종이 부품이고 앱에서 두 장을 합성하는 구조야.

```text
post-card-memory Android 앱의 달력 사이드바에 쓰는 닫힌 스티커 통의 뒷종이 레이어 한 장을 만들어줘. 이것은 종이 배경/재질 부품이며, 실제 가방 사진이나 입체 종이 공예가 아니야. 얇은 신문·잡지 인쇄 종이를 가위로 정돈해 오린 납작한 종이 한 장이야. 자산 A 하나만 출력하고, 앞판·사진 스티커·합성 시트는 넣지 마.

최종 앱 도입 목표는 594×396px, 가로:세로 3:2 RGBA PNG야. 생성 도구가 정확한 픽셀을 지원하지 않으면 같은 3:2 비율로 만들고 실제 출력 크기를 따로 알려줘. 체크무늬를 그리지 말고 실제 투명 alpha 배경으로 만들어. 결과의 리사이즈·crop·앱 적용은 이 제작 요청에 포함하지 않아.

132×88 논리 좌표를 4.5배한 캔버스야. 원점은 좌상단. 종이 외곽 꼭짓점은 논리 좌표 (4,12), (128,11), (127,84), (5,85)이야. 최종 픽셀로는 (18,54), (576,49.5), (571.5,378), (22.5,382.5). 가위질의 작은 흔들림만 허용하고 종이 바깥은 완전히 투명하게 해. 원점을 옮기거나 alpha 여백을 trim하거나 종이를 자동으로 캔버스 가운데 확대하지 마. 중앙축은 x=297px야. 별도 앞판 레이어와 원점·캔버스·양옆·바닥 기준이 맞아야 해.
```

## 111일차 1차 후속 — 파우치 PNG가 정말 필요한가

### 열린/닫힌 파우치 각각의 판단

- **닫힌 파우치(사이드바132×88dp): 지금 필수 아님.** 가장 자주 보이는 진입 대상이라 나중에 종이 재질이 부족하다고 판단하면 우선 비교할 곳이야. 필요성이 확인되면 앞/뒤2장만 제작하고 작은 실제 크기에서 현재안과 비교해.
- **열린 파우치(보관함118.8×79.2dp): 지금 필수 아님.** 닫힌 것보다 작고 보관 조각이 주인공이므로 현행 코드가 충분한 후보야. 닫힌2장 도입이 승인돼도 열린2장 제작·적용을 자동으로 포함하지 않아. 재질의 이질감이 사용자 화면에서 확인될 때 따로 결정해.
- 기존 보관함 바탕 sheet까지 PNG로 바꾸는 건 이번 비교와 별개이며 필요 근거가 없어.

### 시각 품질에 더 크게 영향을 주는 지점

1. **입구와 앞판의 가림:** 조각이 주머니에서 나온다고 읽히는지,누끼/원본·빈 통 모두 자연스러운지가 우선이야. PNG의 미세 결보다 계층·중앙 홈·조각 노출 비율의 영향이 클 수 있어.
2. **스티커와 글자의 대비:** 앞판 인쇄가 스티커·'스티커 통'·개수를 가리지 않아야 해. 너무 진한 신문 결은 오히려 품질을 낮출 수 있어.
3. **실제 표시 크기의 가장자리·톤:** halo,과도한 노랑,두꺼운 외곽·그림자를 피하는 게 중요해. 확대된 PNG 질감만 보고 판단하지 않아.
4. **열기·복귀와 움직임의 감각:** 외형 만족과 별개로 캐시 재생성·약170ms outgoing 흔들림 가능성은 기존 미검증 위험이야. PNG 도입이 이를 해결한다고 말하지 않아. 이번에는 동작을 수정하지 않아.

이 우선순위는 구조와 사용자의 현재 만족 판단에 따른 설계 판단이야. 이번에 기기 화면이나 성능을 새로 측정한 결론은 아니야.

### 결론·승인 항목

코드 드로잉은 현재 역할에 충분한 선택지이며 **지금은 닫힌/열린 모두 유지,필요 신규 PNG0장**을 추천해. 이미지 제작을 미리 진행할 이유가 부족해. 남은 제품 판단은 이 유지 권장안을 채택할지야. 나중에 구체적인 재질 문제가 생기면 닫힌2장 비교안을 먼저 검토하고 별도 적용 승인을 받아. 기존 제작 프롬프트·정렬 명세는 그때 재사용할 수 있어.

### 4. PNG 도입의 순이익 재판단

**권장은 여전히 닫힌·열린 모두 현 코드 유지야. 다만 최종 외형 선택은 새 A/B 목업 사용자 검토 대기야.** B가 실제 크기에서 확실히 더 읽히거나 더 자연스럽다는 사용자 판단을 아직 받지 않았고,재질 증가만으로 도입 이유를 충분히 설명할 수 없어.

| 기준 | 닫힌 파우치 | 열린 파우치 |
|---|---|---|
| 시각 완성도 | 입구·홈·노출된 조각·글자 대비가 우선. 큰 확대에서만 결이 좋으면 이득이 작아. | 작은 정적 보조 표식이라 종이 재질보다 보관 조각이 주인공이야. 현 코드로도 충분한 후보야. |
| 레이어 정렬·가림 | 앞뒤 2장 원점·alpha·캔버스·홈이 정확히 맞아야 해. B의 강제 clip은 실제 제작 성공의 증명이 아니야. | 닫힌 앞판을 재사용하면 앞판 top 44/뒷판 top 4 관계가 달라져. 별도 2장 검수가 필요해. |
| 메모리 | 코드도 캐시 비용이 있어. PNG 594×396 원본 2장 약 1.79MiB, 3x 현 코드 닫힌 2장 약 0.798MiB 대비 약 1MiB 증가 후보. 디코드 정책·GPU 별도. | 같은 594×396을 2장 더 원본 decode하면 추가 1.79MiB 후보지만, 실제 도입 크기와 로딩 정책은 미확정. 작은 표시 크기에 불필요한 원본을 상주시킬 이유가 없어. |
| 관리 복잡성 | 2장 정합·질감·alpha·로딩·테스트 의미의 변경 비용이 생겨. 성능 이득은 미확인. | 닫힘과 열림의 재질 일관성까지 관리해야 해. 닫힌 교체 승인만으로 열린 교체를 포함하지 않아. |

시각 비교 목업의 raster는 원본 종이 PNG를 브라우저가 읽어 쓰므로 **위 Android용594×396 두 장의 메모리 검증이 아니야.** 실제 메모리나APK 증가를 이 HTML로 측정했다고 보고하지 않아.

### 6. 남은 폴리싱과 이미지 제작 승인

- **미완료 폴리싱:** 새 A/B의 실제 크기 사용자 판단, 현 코드를 최종 외형으로 확정할지 여부, 작은 화면·큰 글꼴 가독성, 열린/닫힌 재질 일관성. 기존 캐시 재생성·실메모리·전환 흔들림 위험은 미측정/미검증으로 유지하고 이번에 수정하지 않아.
- **지금 이미지 제작 승인은 필요 없어.** 현재 시안 비교에 필요한 새 그림은 0장이야. 이미지 생성 도구를 사용하지 않았고 코드로 PNG를 구워내거나 새 리소스로 추가하지도 않았어.
- B가 더 낫다고 확인되고 실제 제작 비교가 필요해지면, 목적은 '승인된 질감·외곽을 실제 앞/뒤 alpha 레이어로 맞추고 조각 가림을 검수'하는 것이야. 그때 별도 제작 승인을 받을 최소 수량은 **닫힌 2장**이야. 열린 것까지 선택하면 **추가 2장**, 총 4장 후보가 돼. 기존 594×396 목표는 닫힌 2장 조건부 명세이고 열린 자산 규격을 자동 확정하지 않아.
- 프로덕션 반영·새 기기 QA·Git 마감은 별도 승인 경계야. 이번 HTML의 샘플 조작을 실제 저장/삭제/재사용 검증으로 보고하지 않아. HANDOFF와 달력 산출물은 사용자 지시대로 수정하지 않아.
